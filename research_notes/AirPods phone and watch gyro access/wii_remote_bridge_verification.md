## Missing or contradicted

- **How the Hack the North 2026 AirPod teams built it (question 1).** Neither used anything in these notes: no Dolphin, DSU or virtual gamepad. Aircade (Swift, SwiftUI, SceneKit, Core Motion, OpenAI Responses API) and Poddle (Swift CoreMotion reader, JSON to a WebSocket bridge, browser game) both read `CMHeadphoneMotionManager` on a **Mac** with an earbud held in the hand. The Dolphin/DSU route here is an alternative build for Windows, not their method. Sources: https://github.com/apollo-ullah/Aircade ; https://github.com/danielrltan/poddle .
- **Python DSU servers already exist,** so the "write a minimal server" inference can start from code: adamboy7/DSUwU (Python DSU input, motion and rumble server, last push 2026-03-10), proadress/switch-emulator-phone-control (web pad plus a standard-library Python DSU server, 2026-11-02), Scindix/PyCemuhookMotionServer (2018). Also phone-as-Wii-Remote projects Hndrd0/Andromote (Android, 2026-09-03) and foorpyxof/GGemu_DSU (WebSocket to DSU, 2025-01-22). None were tested here.
- **Pitfalls for a custom DSU server that the notes miss** (all from Dolphin master):
  - Dolphin computes the CRC32 over the full struct size, rejects a length field above 84, and checks the magic and message type, so send exactly the 100-byte data layout.
  - Dolphin asks for the port list from one socket and subscribes from a separate socket per device, so send data to the IP **and port** that each `0x100002` request came from.
  - A device appears only when the `0x100001` reply reports slot state 2 (connected).
  - On each poll, Dolphin reads all queued packets and keeps only the newest one, so sending faster than Dolphin polls adds nothing. A burst after a Wi-Fi gap is collapsed into one sample.
  - Notes' gap resolved: the model byte (1 or 2) is only compared to detect a changed controller; it does not turn motion on or off.
- **Windows 11 permissions:** PadForge always runs elevated and installs HIDMaestro; HIDMaestro needs administrator rights; PhoneGyro needs the firewall prompt accepted (and the Wi-Fi network allowed). This interacts with the notes' UIPI point: if a tool or game runs elevated, a non-elevated SendInput script cannot drive it.
- **AirPods sample rate is contested and not Apple-documented:** Poddle's README says 50 Hz through CoreMotion; AirPodsGyro reports about 100 Hz for AirPods Pro 3 over raw Bluetooth. Check the separate AirPods notes before quoting a number.
- **Question 2 coverage gaps in this file:** nothing on Fitbit, and the Apple Watch point ("a WatchConnectivity relay through the iPhone") is unverified here. The verified phone-to-Windows routes are PhoneGyro and PadForge (browser page, PC is the server, add `127.0.0.1:26760`), and DSUController, AndroidDSU and MotionSourceiOS (phone is the server, add the phone's LAN IP).
- **Question 3 (home motor test):** this file has nothing on it. The reusable parts are the browser sensor path (HTTPS page, `requestPermission()` on a tap, `devicemotion`, WebSocket to the laptop) and the gravity/linear-acceleration filtering. DSU and Dolphin are irrelevant to a walking test.
- **Source contradiction:** the ViGEm EoL page flags every ViGEmBus up to 1.21.442 for the updater leak, while the vgamepad maintainer says 1.17.333 has no auto-updater. Neither page shows the 1.17.333 installer's contents.
